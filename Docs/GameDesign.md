# 게임 디자인 문서 (GameDesign)

> 작성: PM 세션 / 최종 수정: 2026-11-11
> 상태: **초안**. 확정 항목과 미정 항목을 나눠 적었다. 미정 항목은 사용자 답을 받은 뒤 확정한다.
> **게임 룰(승리 조건·체력·공격·스킬 등)은 [GameRules.md](GameRules.md)가 기준이다** (2026-11-13). 장르는 비대칭 대전(감시자 vs 생존자)으로 바뀌었다.

## 1. 컨셉

- **장르:** 3D 격투 게임
- **현재 범위:** 싱글 플레이. 마감 기한이 짧아서 한 명이 로컬에서 플레이하는 형태로 먼저 만든다.
- **확장 계획:** 나중에 멀티플레이(네트워크 대전)로 업그레이드한다. 그래서 지금 코드도 멀티 확장을 염두에 두고 짠다. 원칙은 3장에 적었다.
- **캐릭터:** 제5인격 모델 15종 (`Assets/Models/IdentityV/`, 헌터 8 · 생존자 7). Generic 리그이고 애니메이션은 아직 없다.

## 2. 확정된 내용

### 2.1 조작 — 메인 캐릭터

| 입력 | 동작 | 모션 |
|---|---|---|
| W | 앞으로 이동 | 걷기 |
| A | 왼쪽으로 이동 | 걷기 |
| S | 뒤로 이동 | 걷기 |
| D | 오른쪽으로 이동 | 걷기 |
| 이동 중 Shift (누르고 있는 동안) | 달리기 | 달리기 |
| Space | 점프 | 점프 |
| 마우스 우클릭 + 드래그 | 화면(시점) 돌리기 | — |
| 마우스 좌클릭 (짧게) | 약공격 | 약공격 |
| 마우스 좌클릭 (길게 눌렀다 떼기) | 강공격 | 강공격 (모으기 → 내려치기) |
| (입력 없음) | 정지 | 대기(Idle) |

- 입력은 New Input System으로 받는다.
- **방향 기준은 카메라(플레이어 시야)다.** W는 카메라가 보는 앞쪽, A/D는 카메라 기준 왼쪽/오른쪽, S는 카메라 기준 뒤쪽이다. 높이 성분은 빼고 수평 방향만 쓴다.
- 달리기는 이동 입력이 있을 때만 적용된다. 멈춘 채로 Shift만 누르면 아무 일도 없다.
- 점프는 땅에 닿아 있을 때만 된다. 공중 연속 점프는 없다.

### 2.1.1 공격 (2026-11-12 사용자 확정: 좌클릭 약·강공격)

- 좌클릭 하나로 약공격과 강공격을 모두 쓴다. 구분 방식은 아래 기본값을 쓰고, 사용자 확인 전까지 조정할 수 있다.
  - **약공격:** 좌클릭을 짧게 누르고 떼면 나간다(누른 시간 0.3초 미만). 빠르고 데미지가 낮다.
  - **강공격:** 좌클릭을 0.3초 이상 누르고 있으면 모으기 자세가 되고, 떼는 순간 나간다. 느리고 데미지가 높다. 땅에서 모으는 동안은 걷기 속도로만 움직인다(공중에서는 제한 없음).
- 공격 동작 중에는 새 공격이 나가지 않는다. 약공격 연타(콤보)는 첫 버전에 넣지 않는다.
- **공중 공격 가능** (2026-11-12 사용자 요청 "점프하면서 공격"): 점프 중에도 좌클릭 약·강공격이 된다. 공격 중에도 점프 궤적은 그대로 유지되고, 착지해도 공격은 끝까지 이어진다.
  - **공중 공격 모션은 발로 내려찍기다** (2026-11-12 사용자 확정). 이유는 모션 제작이 편하기 때문이다. 공중 약공격과 공중 강공격은 같은 내려찍기 모션을 쓴다. 강공격은 모으는 자세에서 시작하고 더 세게 내려찍는다.
  - 공중 공격의 때리는 판정은 손이 아니라 **발**(Hitbox_LeftFoot·RightFoot)이다.
- 공격이 나가는 방향은 몸이 보는 방향(시야 Yaw)이다.
- 우클릭(시점 회전)을 누른 채로도 좌클릭 공격이 된다.

### 2.2 카메라 — 3인칭 뒤쪽 시점

- 카메라는 **항상 캐릭터의 등 뒤**에서 캐릭터를 바라본다.
- 마우스 우클릭을 누른 채 드래그하면 시야(카메라)가 돌아가고, **캐릭터도 시야를 따라 같이 돌아서** 계속 등이 카메라를 향한다.
- 우클릭을 누르지 않으면 마우스를 움직여도 시점이 돌지 않는다.
- 가정(사용자 확인 전 기본값):
  - 좌우 회전(Yaw)은 제한이 없다. 상하 회전(Pitch)은 땅을 뚫거나 뒤집히지 않도록 일정 각도(예: -30°~60°)로 제한한다.
  - 캐릭터는 이동 방향이 아니라 **시야 방향**을 바라본다. 그래서 A/D는 옆걸음, S는 뒷걸음이 된다.
  - 우클릭 드래그 중에는 마우스 커서를 숨기고 고정한다.
  - 카메라와 캐릭터 사이에 벽이 끼는 경우의 처리(카메라 당겨오기)는 M1 범위 밖이다.

## 3. 멀티 확장을 위한 구조 원칙

BE와 FE 모두 이 원칙을 따른다.

1. **입력과 행동을 분리한다.** 키보드 입력은 "입력 데이터"(예: 이동 방향 Vector2, 공격 버튼 여부)로만 바꾼다. 캐릭터는 그 데이터만 받아서 움직인다. 나중에 키보드 입력 대신 네트워크 입력이나 AI 입력을 같은 자리에 꽂으면 된다.
2. **캐릭터 로직은 누가 조종하는지 모른다.** 플레이어, AI, 원격 플레이어가 같은 캐릭터 코드를 쓴다. "로컬 플레이어인지"를 캐릭터 코드 안에서 분기하지 않는다.
3. **게임 상태는 한 곳에서 관리한다.** 라운드 진행, 체력, 승패 같은 상태는 매니저 하나가 소유한다. UI와 연출은 그 상태를 읽거나 이벤트를 구독하기만 하고 직접 바꾸지 않는다. 나중에 서버가 이 상태를 소유하게 바꾸기 쉽다.
4. **게임 로직과 연출을 분리한다.** 판정(이동, 피격, 데미지)은 BE의 `Core/`·`Systems/`에 두고, 애니메이션·이펙트·UI·카메라는 FE의 `Presentation/`·`UI/`에 둔다. 연출이 빠져도 게임 로직은 돌아가야 한다.
5. **결정적인 업데이트를 지향한다.** 이동과 판정은 `FixedUpdate`(고정 틱)에서 처리하고, `Random`처럼 결과가 매번 달라지는 요소는 한 곳을 거치게 한다. 나중에 동기화나 롤백을 붙이기 쉽다.
6. **플레이어를 번호(슬롯)로 구분한다.** "Player 1 / Player 2"처럼 슬롯 ID로 캐릭터와 입력을 연결한다. 싱글에서는 P2를 AI가 맡는다.
